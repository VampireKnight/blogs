如何跨本地项目开发

我们在开发项目的时候,有时候会同时分模块开发,我们如何进行跨本地项目开发

例如:我们开发同时开发一个模块和一个项目,项目需要使用到这个模块 如果,我们使用相对路径,那么后期就涉及到项目路径替换的问题: 开发时:我们使用的是本地相对路径 发布时:我们的模块包可能会上git/npm,也就是说它最后会生成一个npm包来被项目使用 本地路径和模块路径是不一样的,我们需要替换掉路径:开发路径和发行包路径完全不一样

(不推荐)项目安装本地模块

第一步:在配置本地模块路径

在Package.json中配置dependencies 模块名:file:+本地模块相对路径Package.json

{
  // ...

  "dependencies": {
    // ...
    "temp-custom-module": "file:../../modulePackages"
    // ...
  }
  // ...
}

第二步:安装

yarn install
npm install

报错:Can't add "temp-custom-module": invalid package version "".

这个问题看起来就是 模块未设置 版本

模块中的Package.json添加版本

{
  // ...
  "version": "0.0.1"
  // ...
}

第三步:运行

我们发现:它会整个安装到node_modules中,也就是说,它是复制了一份原模块代码,跟原模块是独立的 如果源模块修改了,项目中的模块并没有同步更新

补充命令

# yarn 移除 模块
yarn remove temp-custom-module

符号链接（Symlink）

使用npm link命令创建本地模块与项目的符号链接，适用于开发阶段频繁修改本地模块的场景：

在目标项目目录中执行 npm link local-module-name，将本地模块链接到项目依赖中

第一步:在本地模块目录中执行 npm link，生成全局符号链接。

查看本地npm 包的位置

查看所有全局安装的 npm 包：npm list -g --depth=0我们使用的nvm,查看路径:E:\NodeVersions\NVM_Manager\v1.1.11\nvm\node_global\node_modules

在模块项目中执行命令 例如:模块项目为:I:\D_Private\stock-project\modulePackages

进入项目中,执行命令:npm link

解决报错:在 Package.json中添加模块名称

{
  // ...
  "name": "stockFoundationPackages"
  // ...
}

再次执行命令 在本地模块目录中执行 npm link，生成全局符号链接。

再次在全局npm包目录中查看

第二步:在项目中使用 npm link 前面的模块

在项目中执行命令 例如:开发项目路径 为:I:\D_Private\stock-project\stockKoaService\stockKoaServiceProject>

进入项目中,执行命令:npm link stockFoundationPackages

第三步:验证是否是软连接

我们发现使用了 link 模块命令后,项目的node_modules中似乎安装了模块

那么,它是否真的是软连接呢,我们可以验证下

在模块根目录中创建一个文件linkTest.ts

export const linkTestData = {
  data: "这是linkTestData对象",
};

本地全局对应的npm包

我们发现它确实新增了这个文件

项目node_modules中的npm包

我们发现它确实新增了这个文件 注:如果目录没显示出来,可以刷新一下(可能在修改之前打开了目录,显示的没变,windows系统是有这样的情况)

补充说明

npm link xxx后的项目并不是一个稳定的状态,

如果项目后续安装其他的包的时候,重构依赖,由于 xxx 并不是显式地 存在 package.json中,重构的时候可能会丢失 此时,再次执行 npm link xxx

总结

跨本地项目开发,有两种方式:

方式一:本地安装

配置Package.json中模块和本地路径

是否是软连接:暂时未验证

方式二:使用npm link软连接

这种方式不会在Package.json中添加模块

不熟悉项目的人可能并不知道需要这个模块

由于是软连接,所以 模块代码是同步更新的
